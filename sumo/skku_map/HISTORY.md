# 성대역 SUMO 도로망 — 만든 과정과 시행착오

박준수 작업 정리 (2026-10 말 ~ 2026-11-02). 팀원이 이어서 볼 수 있도록 **어떤 방법을 시도했고, 왜 바꿨는지**를 순서대로 적었다.
지금 쓰는 결과물은 `skku_map/` 하나다. 나머지 폴더는 앞선 시도라 참고용으로만 남겼다.

| 폴더 | 시기 | 방법 | 상태 |
|---|---|---|---|
| `skku_area/` | 1차 | OSM 지도를 netconvert로 통째로 불러오기 | 버림 (참고용) |
| `skku_schematic/` | 2차 | 교차로·도로 연결을 손으로 정의 + 모양만 OSM에서 | 버림 (참고용) |
| `underpass/` | 2차 중 | 지하차도 표현 실험용 작은 도로망 | 실험 |
| **`skku_map/`** | **3차 (현재)** | OSM에서 범위 안 차도만 잘라 불러온 뒤, 지도로 확인한 것만 수정 파일로 덧입힘 | **사용 중** |

---

## 1차: `skku_area` — OSM 통째로 불러오기
- OSM 공식 API로 받은 지도(`skku.osm.xml`)를 netconvert 권장 옵션으로 불러옴. 도로 1,072개.
- 문제
  - 골목·단지 안 도로까지 모두 들어와 너무 복잡하고, 막다른 길에서 차가 돌아 나오는 등 이상한 움직임이 많았다.
  - `--osm.layer-elevation`이 고가·지하차도 높이를 **이웃 도로까지 경사로로 퍼뜨려** 사거리 전체가 떠 보였다.
  - 고속화도로(봉담과천로)를 실제 길이(사당까지 약 23 km) 그대로 넣기 어려웠다.

## 2차: `skku_schematic` — 연결은 손으로, 모양은 OSM으로
- 교차로(노드)·도로(엣지)·차로·신호·주차장을 코드에서 직접 정의하고, 도로 모양만 OSM 선을 따라 꺾었다 (`osm_shapes.py`).
- 이때 정한 것 (지금도 유지)
  - **사거리 신호(사용자 지정)**: 차량 네 방향 동시 녹색 70초(서부로 직진·우회전 우선, 나머지 양보) → 황색 3초 → 보행자 동시신호 45초.
    신호 계획을 netconvert `-i`로 다시 넣어 교차로 우선권을 신호에 맞춘다.
  - 학교 차량 출입은 정문만 (후문·서쪽 문 막힘: 카카오 길찾기로 밖→안 경로가 정문으로 돌아가는 것 확인).
  - 고가 밑 공영주차장 3곳, 고가 밑 갈림목 G1~G3의 유턴(카카오 길찾기로 확인한 곳만).
- 문제: 골목을 하나씩 손으로 붙이다 보니(`minor_roads.py`, 415개) 연결·이름 관리가 감당이 안 되고, 손으로 만든 연결과 실제 지도가 어긋나는 곳이 계속 나왔다.

## 3차 (현재): `skku_map` — OSM 잘라오기 + 확인한 것만 덧입히기
`build.py` 한 번 실행으로 처음부터 끝까지 다시 만든다 (`python -X utf8 build.py`).

1. `osm_clip.py`: 사용자가 지도에 그린 범위 안의 차도만 잘라 옴. 카카오로 확인한 일방통행·차로 수 표(`LANES_VERIFIED`) 반영,
   왕복 분리 도로 두 줄을 실제처럼 붙이기, 단지 안 막다른 골목·아주 작은 길 빼기.
2. netconvert로 불러오기 (원점 = 성대역 사거리, 단위 m).
3. 수정 파일(`patch.*.xml`): 신호, 유턴, 회전 금지, 고가 밑 주차장, 서부로 고가, 고속도로, 높이.
4. 교통: 고속도로 흐름 + randomTrips(일반 차량, 경계 큰길 위주) + 주차 차량 + 버스(카카오 실제 노선 17개).

### 지도 확인 방법 (규칙)
- 도로 연결·일방통행·유턴은 **카카오맵 길찾기로 직접 경로를 찍어** 확인 (네이버 지도는 앱 브라우저에서 차단).
  - 주의: 짧은 구간 길찾기의 '돌아감'은 일방통행 근거가 아니다. 카카오가 도착점을 반대 차로에 붙여 유턴해 오는 경우가 있어
    화산로·만석로·정자천로·일월로를 잘못 일방통행으로 만든 적이 있다 → 길 앞뒤로 멀리 찍은 긴 경로로 판정.
- 차로 수는 카카오 스카이뷰(위성사진)로 셌다. 결과는 `WORKLOG.md`의 "차로 조사".
- **차로 구성(차로 수·차로별 방향·합류)은 지도로 확인하지 않고 바꾸지 않는다.** (정체를 풀려고 사거리 북쪽 차로를 임의로 '좌회전 전용'으로 바꿨다가 되돌림)

### 주요 시행착오 (자세한 기록은 `WORKLOG.md`)
| 문제 | 원인 | 해결 |
|---|---|---|
| 사거리 한복판 정체 | 동시 녹색이라 교차로 안에서 서로 양보하며 멈춤 + 고속도로 유출입 700대/h가 사거리 통과 | 고속도로↔지역 유출입을 줄이고, 지역으로 드나드는 고속도로 차는 대부분 사거리 직진 → 서부로 고가로 지나가게 |
| 사거리 전체가 떠 보임 | `--osm.layer-elevation`이 높이를 퍼뜨림 | OSM `layer` 태그가 있는 길과 겹치는 엣지만 ±6 m |
| 요금소 차로가 계단처럼 한 칸씩 늘어남 | 차로 수를 한 단계씩 바꿈 | 3↔10차로 깔때기 모양 교차로 하나(노드 `shape`), 줄어드는 곳은 `zipper`(번갈아 합류). 보통 교차로로 두면 10→3 합류가 막혀 지연 63~70초 |
| 의왕IC 램프가 날아다님 → 반쪽 다이아몬드로 줄였지만 여전히 어색 | 실제 IC 모양을 따라 하려 함 | **사용자 지정**: 고속도로는 유령 제동·요금소 실험용 일자 도로면 충분 → IC를 빼고 서부로 북쪽 끝에 그대로 이음 |
| 서부로 고가가 철길 위에서 겹침 | OSM에 그 구간이 4차로로 적혀 두 방향이 겹쳐 그려짐 | 위성사진으로 2+2 확인 후 고가 가운데선 기준으로 다시 그림 |
| 고가가 중간에서 끊김 (차가 고가를 끝까지 못 감) | OSM 중간 노드 둘이 `dead_end`로 잡혀 연결이 없었음 | 방향마다 사거리~삼성아파트 앞까지 엣지 하나(`via_sb`, `via_nb`)로 다시 만듦 |
| 고가가 지상 교차로와 이어진 것처럼 보임, 지하차도가 지상 도로 위로 보임 | sumo-gui는 도로망 전체를 한 층에 그려 높이로 앞뒤를 못 가림 | 고가·지하차도 차로는 투명하게 두고 도형으로 직접 그림: 지하차도 면은 도로망 밑, 숨은 선(점선)은 위 / 고가 면은 반투명으로 위 |
| G1~G3에서 고가가 여전히 끊겨 보임 | 신호 교차로 면이 layer 3.5 도형보다 위에 그려짐 (화면 확인) | 고가 도형을 layer 15로 올림 |
| 높이 표현을 어떻게 할지 | 방안 4개(A 투명 / B 지도식 / C 들어올려 그리기 / D 선만)를 같은 세 곳에서 캡처해 비교 | **사용자 선택: B 지도식** — 고가는 불투명+테두리+그림자, 고가 옆 지상도로는 3 m 띄우고, 아래층 도로·차는 옅게(차는 view_skku.py가 TraCI로) |
| 고가 밑 서쪽 G1~G2 도로가 1차로 | OSM lanes=1 | 사용자 로드뷰로 2차로 확인 → `LANES_VERIFIED` |
| 고가 밑 주차장 입구·출구가 실제와 반대 | 갈림목에서 들어가 다음 갈림목으로 나오게 일괄로 만들었음 | 카카오 장소 좌표·'입구' 표시 + 로드뷰 사진으로 주차장마다 다시 (P1 출구만 미확인) |
| 버스가 주차장 통로로 들어감 | 통로를 모든 차에 열어 두어 버스 노선 5개가 지름길로 씀 | 통로는 vClass taxi만, 주차 차량 vType을 taxi로 |
| 주차 차량 순간이동 | 칸 수보다 많은 차를 한 구역에 배정 → 막다른 통로에서 대기 | 빈 칸이 있는 구역에만 배정 |
| 새로 만든 엣지 차로가 한 칸 옆으로 밀림 | OSM 일방 도로는 `spreadType="center"`인데 새 엣지는 기본값(right) | 새 엣지에도 `spreadType="center"` |
| 사거리 정지선이 비스듬함 | netconvert가 만든 교차로 면이 비뚤어진 사각형 | 교차로 면을 도로 방향(약 7도 기울어짐)에 맞춘 직사각형으로 (노드 `shape`) |
| 주차면이 사선 | sumo-gui의 `<space angle>` 해석 | 긴 변이 (angle+90)도로 그려짐을 화면으로 확인 → angle = 통로 방향 |
| 지명이 네모로 깨짐 | sumo-gui 글꼴에 한글이 없음 | 영어로 (큰 곳은 직접 번역, 나머지 로마자) |

### SUMO 화면에 대해 알아낸 것 (1.27.1, 화면으로 확인)
- 도형(`<poly>`) layer 1은 교차로 면 **밑**, layer 3 이상은 교차로 면 **위**에 그려진다. 도로망 자체는 layer 0 (userdoc/Simulation/Shapes.html).
- 차량은 layer 6 도형보다도 위에 그려진다 → 고가 밑 차도 고가 위에 보인다.
- 노드 `shape`를 주면 netconvert가 엣지를 그 면에서 자른다 (정지선 위치를 직접 맞출 수 있음).
- 신호 교차로 면은 layer 3.5 도형보다도 위에 그려졌다 → 고가 도형은 layer 15 (그래도 차량보다는 밑).
- 차 색에 투명도(alpha)를 주면 sumo-gui에서 반투명하게 그려진다 (TraCI `vehicle.setColor`). 보기 설정에는 높이별 차 색이 없다.
- 설치된 1.27.1에는 3D 보기(OSG)가 없다 (빌드 정보에 OSG 없음). 3D 빌드는 sumo-win64extra-git.zip(개발판)으로 따로 있다.

## 아직 남은 것
- 최종 점검(1시간 × 3회, 2026-11-02 밤): 순간이동 0, 평균 지연 62~69초.
- 고가 밑 주차장 1(율전제3공영)의 출구 위치는 지도로 확인하지 못해 가정함 (G1 앞 북행 도로로 우회전).
- 덕영대로 서행 → 사거리 진입 대기열이 김 (교착은 아님), 서부로×일월로(고가 남쪽 끝)도 막힘. 차로 구성 변경은 지도 확인이 필요해 손대지 않음.
- 고속도로 본선 교통량이 한 방향 약 1,000~1,200대/h로 유령 제동(정체파) 실험에는 조금 성길 수 있음.
  더 촘촘하게 하려면 청계IC 진출입로를 2차로로 늘리거나 본선 위에서 차를 출발시키는 방법을 검토 (`write_routes()`의 봉담과천로 흐름).
- 수업 저장소(bmil-ssu) 쪽 고속도로 환경 수정(`env/`, `view_road.py`, 학습 스크립트)은 `../course_repo_changes/`에 보관만 함 (수업 코드 위에 덮어쓰는 변경분).
