## 🎯 한 문장 요약

- **중간발표**: "왜 이 도로를 선택했고, 어떤 자율주행 문제가 발생하는가?"
- **최종발표**: "그 문제를 실제 SUMO 환경으로 구현하고, AV가 안정적으로 주행하며, 사용할 수 있는 데이터까지 만들었는가?"

> **복잡한 도로보다, 프로젝트의 목적과 차량 interaction이 명확하게 드러나는 환경을 높게 평가한다.**

동료 평가가 보는 흐름:
```text
왜 이 도로를 선택했는가?
        ↓
어떤 Vehicle Interaction이 발생하는가?
        ↓
AV가 해당 상황을 안정적으로 해결하는가?
        ↓
그 과정이 데이터에 잘 기록되어 있는가?
```

## 1. 중간발표 (3분)

목적: **프로젝트 방향에 문제가 없는지 확인** (도로 선정, 차량 interaction, 데이터 구성이 프로젝트 목적과 맞는지)

### 반드시 담을 내용
| # | 내용 | 핵심 |
|---|---|---|
| 1 | **선정한 실제 도로** | 지역 + 지도·실제 도로 이미지 |
| 2 | **도로의 구조적 특징** | 삼거리·사거리·회전교차로·합류·분기·다중 차선·차로 감소 등 **모듈의 조합으로 설명**. "자율주행 환경으로 구현했을 때 어떤 구조적 특징이 있는가" |
| 3 | **왜 흥미로운 도로인가** | 유명한 장소라는 것만으로는 부족. **자율주행 의사결정 문제로서 왜 의미 있는지** 설득 |
| 4 | **어떤 차량 interaction이 발생하는가** | **어느 구간에서 무엇이** ("직진 ↔ 좌회전", "합류 ↔ 본선", "느린 차 추월"). 도로 구조 → interaction → AV 의사결정이 이어져야 함 |
| 5 | **수집할 데이터 컬럼** | Episode, Step, Ego position/speed/lane, 주변 차량 정보, Action, Reward, Next State, Done 등. **State(절대적인 정보) 컬럼은 반드시 포함** |
| 6 | **팀 이름과 역할 분담** | **1페이지**로. 누가 어떤 부분을 중심으로 맡는지 |

> **교수님 힌트: "눈치 게임"이 많을수록 AI에게 어렵다.** 여러 방향에서 차량이 동시에 진입해 서로 양보하고 끼어들어야 하는 구간일수록 자율주행 문제로서 가치가 크다.

### 발표 운영 규칙 (엄격)
- **3분 초과 시 즉시 중단**
- 발표 자료는 **과제함 제출 → 교수님 PC로 진행. USB 불가.** 제출 마감 **수업 시작 15분 전**
- 슬라이드·영상 확인은 수업 10분 전 강의실 PC에서 (줄 서서)
- 파일 문제로 지체하면 **그 시간만큼 발표 시간 차감**
- **슬라이드는 적게.** 화려함보다 정보 전달. 발표자가 자주 바뀌지 않게

### 슬라이드 구성 예시 (참고용, 자유)
```text
Slide 1  팀 이름 / 팀원 / 역할 분담
Slide 2  선정 지역 + 실제 도로 이미지
Slide 3  도로 구조적 특징 + SUMO 구현 계획
Slide 4  예상 차량 interaction + 자율주행 문제
Slide 5  수집 데이터 컬럼
```

## 2. 최종발표 (13분)

**도로 구축 → 차량 interaction → AV 학습 → 평가 → 데이터 수집** 전체 과정을 보여준다. 중간발표 내용 포함, 최소한:

- 선정한 실제 도로와 구현한 SUMO 환경, 도로 구조적 특징
- 일반 차량 구성
- AV Observation / Action / Reward, 학습 방법
- 정량적 주행 성능: **Collision Rate, 보상 값, 목적지 완주 여부**
- **실제 주행 영상 30초 이상 (필수)** — 도로 구조, 일반 차량 움직임, AV 움직임, 차량 interaction, **목적지까지의 주행**이 보여야 함
- 수집 데이터 설명
- **프로젝트에서 발견한 문제와 해결 과정**

## 3. 최종 통과 기준

| 기준 | 내용 |
|---|---|
| **Collision Rate < 5%** | 예: 100 에피소드 평가 중 충돌 4번 → 4%. (6장 "< 5%", 10/27 공지 "5% 이하" → **5% 미만을 목표**) |
| **목적지 완주** | Start → Goal을 문제 없이 |
| **비정상 동작 없음** | 잘못된 Route로 빠지기, 특정 위치 무한 대기, **사고는 없는데 혼자 가만히 서 있기 = 의미 없음** |
| **충분한 일반 차량** | AV 혼자 주행 X. **의도한 구간에서 interaction이 실제로 발생**해야 함. 대수·밀도의 숫자 기준은 없음 → **영상으로 납득**시킨다 (꼼수는 통하지 않음) |
| **도로 형태** | 제한 없음 — Open Road, Loop Road, Intersection, Roundabout, Merge/Diverge 모두 가능 |
| **신호등** | 추가 가능. **추가하면 State 컬럼에 신호 상태를 반드시 포함** |

## 5. 동료 평가 (최종발표, 다른 팀이 평가 — 내용 90점 + 발표 10점)

10/27 공지 기준 배점: **도로 구조 및 설계 20점, 일반 차량 ↔ AV 상호작용 20점**, 나머지(데이터, 주행 결과·문제 해결, 발표)는 미정.
총점으로 **상 3팀 / 중 5팀 내외 / 하 9팀 내외**로 분류한다. 평가자는 **웹 페이지에 들어가 보고, 데이터를 내려받고, 코드에 꼼수가 있는지도 본다.**

| 항목 | 내용 |
|---|---|
| 도로 구조 설계 및 구현 | 실제 도로의 구조적 특징 반영, **도로 선정 이유**, 자율주행 문제로서 흥미로운 구조 |
| 일반 차량 구성 및 상호작용 | 일반 차량과 AV 사이에 **합류, 양보, 차선 변경, 교차로 통과** 등 의미 있는 interaction이 충분한가 |
| 데이터 수집 항목 설계 | 항목별 **의미·단위·저장 구조**, 각 항목의 필요성, 수집 규모·조건 |
| 주행 결과 및 문제 해결 | 영상과 정량 결과로 충돌·비정상 정지 없이 목적지까지 완주, **겪은 문제와 해결 방법**을 구체적으로 |
| 발표 (10점) | 준비도, 시간 준수, 핵심을 제한 시간 안에 이해하기 쉽게 |

## ✅ 결정할 때마다 쓰는 점검표

도로·구현·보상·데이터·발표 관련 결정을 할 때 아래 질문으로 검토한다.

1. **도로 선정 이유**가 "유명해서"가 아니라 **자율주행 의사결정 문제**로 설명되는가?
2. **도로 구조 → 차량 interaction → AV 의사결정**이 한 줄로 이어지는가?
3. **일반 차량이 충분히** 있고, AV와 **합류·양보·차선 변경·교차로 통과** 같은 interaction이 실제로 생기는가?
4. AV가 **Start → Goal 목적지 완주**를 할 수 있는 구조인가? (비정상 정지, 잘못된 Route, 무한 대기 없음)
5. **Collision Rate < 5%** 가 현실적으로 가능한 난이도인가? (복잡성보다 명확성)
6. 시뮬레이션이 **안정적**인가? (정체·Teleport·오류 없음)
7. 데이터 컬럼에 **State(절대 정보)** 와 **조교 공개 컬럼**이 모두 있고, 추가 컬럼은 **이유**를 설명할 수 있으며, **계산으로 얻을 수 있는 중복 컬럼**은 뺐는가? 신호등이 있으면 **신호 상태 컬럼**이 있는가?
8. **30초 주행 영상**에 도로 구조, 일반 차량, AV, interaction, 목적지 도착이 다 담길 수 있는가?
9. 겪은 **문제와 해결 과정**을 [진행 계획](roadmap.md)에 기록하고 있는가? (최종발표·동료평가 항목)
10. 여러 방향에서 동시에 진입해 양보하고 끼어드는 **"눈치 게임" 구간**이 있는가? (교수님 힌트 — 문제로서의 가치)
11. 발표 자료가 **시간 안에 정보가 전달되게 적은 장수**인가? (중간 3분 엄수, 최종 13분 내외)
12. 최종 결과물을 **과제함 + 온라인(페이지·GitHub·Hugging Face) 이중 제출**할 준비가 되어 있는가? (모델 가중치 포함)
