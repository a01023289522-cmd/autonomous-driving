## 할 일 순서

### A. 중간발표까지 (약 2주)

중간발표의 핵심은 **"왜 이 도로이고, 어떤 자율주행 문제가 생기는가"** 다. 이 단계에서는 구현보다 **선정과 설계**가 중요하다.

**A-1. 팀 세팅**
- [ ] 팀원 전원 저장소 초대 수락
- [ ] 팀원 전원 Git 프로그램 준비 + Clone ([Git 협업 가이드](git_guide.md), GitHub Desktop 권장)
- [ ] 팀원 전원 수업 코드 실행 확인 (`python view_road.py`)
- [ ] 팀 이름 정하기:
- [ ] 역할 분담 ([README 팀원 표](../README.md#-팀원) 채우기)
- [ ] 정기 회의 시간 정하기:

**A-2. 도로 선정** — 각자 후보 1~2개 조사 → 회의에서 비교 → 하나로 결정

| 후보 | 위치 | 구조 (사거리/로터리/합류 등) | 생기는 interaction | AV 의사결정 문제 | 걱정되는 점 | 제안자 |
|---|---|---|---|---|---|---|
| | | | | | | |
| | | | | | | |

- [ ] 보여줄 한국 도로 특징 고르기 ([한국 도로의 특징](korean_road_features.md)):
- [ ] 최종 선정:
- [ ] 실제 도로 자료 정리 (지도·로드뷰 캡처, 차로 수, 제한속도)

**A-3. 문제 정의** — 도로 구조 → 차량 interaction → AV 의사결정
- [ ] 도로의 구조적 특징 정리
- [ ] 발생하는 차량 interaction 정리 (합류, 양보, 차선 변경, 교차로 통과 등)
- [ ] AV의 출발점·목적지(Start → Goal)와 AV가 해야 할 의사결정
- [ ] 단순화 범위 결정 (차로 수, 포함할 진입로, 신호등 여부 — 충돌률 < 5% 가능한 난이도인지)

**A-4. 데이터 컬럼 설계**
- [ ] 수집할 컬럼 목록 (Episode, Step, Ego position/speed/lane, 주변 차량, Action, Reward, Next State, Done …)
- [ ] **State(절대 정보) 컬럼 포함** 확인
- [ ] 컬럼별 의미·단위 정리

**A-5. SUMO 구현 계획**
- [ ] 구현 방식: 방식 A(`road_builder.py` 확장) / 방식 B(netedit·외부 파일) ([개요 5절](project_overview.md#도로-구현-방식-팀이-정해야-함))
- [ ] 노드·엣지·차선·연결 대략적인 스케치

**A-6. 중간발표**
- [ ] 슬라이드 5장 (① 팀·역할 ② 지역·도로 이미지 ③ 구조 특징·구현 계획 ④ interaction·자율주행 문제 ⑤ 데이터 컬럼)
- [ ] 3분 리허설
- [ ] 발표 후 교수·조교 피드백 기록 (아래 결정 기록)

### B. 최종발표까지 (중간발표 ~ 11/28)

**B-1. 도로 구현**
- [ ] Node / Edge / Lane / Connection
- [ ] 신호등 (필요 시 — [신호등 기본 사용법](sumo_reference.md#신호등-기본-사용법))
- [ ] 모든 Route 단독 주행 확인 (`python view_road.py --nogui`)

**B-2. 일반 차량 (HV)**
- [ ] 방향별 Route와 교통량 — **충분한 수**의 일반 차량
- [ ] Krauss / IDM / EIDM / ACC 구성
- [ ] 정체·Teleport·투입 대기 없는지 확인

**B-3. AV 환경**
- [ ] AV Start → Goal Route, 도착 판정
- [ ] `sumo_env.py`의 직선 도로 전제 부분 수정 (Route 이름, 도착 판정, prefill)
- [ ] Observation / Action / Reward 검토
- [ ] 1 에피소드 점검 (`collect_pomdp_data.py --policy keep-lane --episodes 1 --gui`)

**B-4. 학습**
- [ ] 작은 규모 학습으로 전체 흐름 확인
- [ ] 본 학습 (PPO)
- [ ] 비교 실험 (아래 실험 기록 표)

**B-5. 평가**
- [ ] 100 에피소드 이상 평가 — **Collision Rate < 5%**, **목적지 완주** 확인
- [ ] **30초 이상 주행 영상** 녹화 (도로 구조, 일반 차량, AV, interaction, 목적지 도착이 보이게)

**B-6. 데이터**
- [ ] 학습 모델로 주행 데이터 수집 (`collect_pomdp_data.py --model ... --episodes 100`)
- [ ] 컬럼별 의미·단위·저장 구조 문서화
- [ ] Hugging Face 업로드

**B-7. 최종 제출물**
- [ ] 코드 정리 (Environment / Training / Evaluation / Data Collection 구분)
- [ ] 저장소 공개 전환 (프로젝트 페이지·코드 제출용)
- [ ] 프로젝트 페이지 (GitHub Pages)
- [ ] 최종발표 슬라이드 (13분) — 문제와 해결 과정 포함
- [ ] 리허설

## 코드 작업 시작 방법 (정해지면 채우기)

수업 코드는 계속 업데이트되므로 지금은 이 저장소에 넣지 않았다. 코드 작업을 시작할 때 아래 중 하나로 정한다.
최종 제출물은 **이 저장소만으로 환경을 재현할 수 있어야** 한다.

- **안 1.** 시작 시점의 수업 코드를 이 저장소에 복사하고, 이후 수업 업데이트는 필요한 부분만 골라 반영
- **안 2.** 우리가 고친 파일만 이 저장소에 두고, 수업 코드 폴더에 덮어써서 실행 (최종 제출 전에는 안 1 형태로 합쳐야 함)
