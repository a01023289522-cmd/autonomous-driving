## 1. 확정 사항

| 항목 | 결정 |
|---|---|
| AV 경로 | 서부로 남행(성대역 사거리 약 300 m 앞) – 성대역 사거리 – 버스 구간 – 올리브영 사거리 – 골목 오거리 3곳 – 회전교차로 – 서부로×일월로 – 정문 – 교내 L1 주차장 통로, 약 2.8 km |
| 도착 | L1 주차장 통로 끝 도달. 주차 칸 진입 동작은 없음 |
| 고속도로 | AV 경로에서 제외. 도로망에는 남겨 일반 차량 진입로로 사용 (삭제하면 사거리 교통량이 바뀜) |
| 학교 동쪽 도로 | 유지. 삭제해도 학습 속도 변화가 작음 (실행 시간의 약 90%가 AV 주변 조회) |
| 교내 순환로 | 경로에서 제외 (통행량 시간당 2–4대) |
| 교통량 | 현재 설정 (초기 10–15분 증량 후 유지하는 시간대 배율) |
| 신호 | 현재 가정값 (`sumo/skku_map/README.md`) |
| 에피소드 길이 | 최대 1600스텝(800초). 경로 평균 주행 약 8분과 여유 시간 |

변경은 팀 합의 후 이 표를 수정한다.

## 3. 초기 설정

SUMO와 수업 코드 패키지는 주차별 과제에서 설치한 상태를 전제로 한다.

1. 팀 저장소 main을 pull한다.
2. 팀 저장소 옆에 수업 저장소를 둔다(폴더 이름 유지). 다른 위치면 환경변수 `COURSE_REPO`에 경로를 지정한다.
   ```
   상위폴더/
     autonomous-driving/
     Artificial-Intelligence-and-Control-for-Autonomous-Driving/
   ```
3. 팀 저장소 최상위에서 실행을 확인한다. 첫 실행은 배경 교통 상태 저장 때문에 몇 분 걸린다.
   ```
   python -X utf8 rl/train_skku.py --config example --timesteps 2048
   ```

| 오류 메시지 | 조치 |
|---|---|
| 수업 저장소를 못 찾았습니다 | 폴더 위치 확인 또는 `COURSE_REPO` 지정 |
| SUMO_HOME 관련 오류 | `echo %SUMO_HOME%`로 설정 확인 |
| 한글 깨짐 | 명령에 `-X utf8` 추가 |

## 4. 실행 명령

전체 명령 표는 [개념 정리 7장](concepts.md#7-실행-명령)에 있다. 자주 쓰는 명령은 다음과 같다.

| 용도 | 명령 |
|---|---|
| 학습 | `python -X utf8 rl/train_skku.py --config 설정이름` |
| 주행 화면 | `python -X utf8 rl/test_skku.py results/폴더/model.pt --config 설정이름 --episodes 3` |
| 100 에피소드 평가 | 위 명령에서 `--episodes 100 --nogui` |
| 학습 곡선 | `tensorboard --logdir results` |

## 5. 주행 화면 조작 (sumo-gui)

에피소드마다 창이 새로 열리고 자동 재생되며, 화면은 AV(빨간 차량)를 따라간다. 근거: `userdoc/sumo-gui.html`

| 기능 | 조작 |
|---|---|
| 일시정지, 재생 | 상단 ■, ▶ 버튼 |
| 한 스텝(0.5초) 진행 | 일시정지 후 `Ctrl + D` |
| 재생 속도 | 상단 Delay 값, `Page Up` / `Page Down`. 0이 최고 속도 |
| 확대, 축소 | 마우스 휠, `+` / `-` |
| 화면 이동 | 마우스 왼쪽 버튼 끌기, 방향키 |
| 다른 차량 추적 | `Shift + 클릭` (해제: 더블클릭) |
| 차량·도로 정보 | 우클릭 |
| 도로 ID 검색 | `Ctrl + E` |

## 7. 변경 항목별 영향

| 변경 위치 | 예 | 영향 | 재학습 |
|---|---|---|---|
| 설정 `REWARD` | `collision_penalty` | 학습되는 주행 습관 | 필요 |
| 설정 `HPARAMS` | `gamma`, `lr` | 학습 속도, 안정성 | 필요. 네트워크 크기 변경 시 기존 모델 사용 불가 |
| 설정 `OBSERVATION` | `visibility` | AV의 관측 거리 | 필요 |
| 설정 `SIMULATION` | `max_steps` | 에피소드 최대 길이 | 학습에 적용 시 필요 |
| 설정 `SIMULATION` | `gui_delay` (`--delay`와 동일) | 화면 재생 속도 | 불필요 |
| 설정 `SCENARIO` | `start_edge`, `goal_edge` | AV 경로 (`--start`와 동일) | 학습 경로 변경 시 필요 |
| 설정 `SCENARIO` | `warmup_seconds` | 출발 시점 교통량 | 필요. 저장 상태는 자동 재생성 |
| `rl/skku_env.py` | 관측 항목 추가 | 정책 입력 개수 | 필요. 기존 모델 사용 불가 |
| `sumo/skku_map/traffic.py` 등 | 교통량, 신호 | 도로·교통 | 필요. `sumo/skku_map`에서 `python -X utf8 build.py --no-check` 실행 |

실험마다 `rl/configs/`에 새 설정 파일을 만들고 변경할 값만 적는다. `base.py`는 수정하지 않는다.

```python
# rl/configs/보상_01.py
TOTAL_TIMESTEPS = 50_000
REWARD = {"collision_penalty": 20.0}
HPARAMS = {"gamma": 0.995}
```

## 8. 학습 중·학습 후 확인 사항

**학습 중**

| 항목 | 내용 |
|---|---|
| 콘솔 출력 | 업데이트마다 `ep_rew_mean`(평균 보상), 10회마다 간이 평가(충돌률, 완주율) |
| TensorBoard | `ep_rew_mean` 상승 여부, 평가 충돌률 하락 여부 |
| 중단 | `Ctrl + C`. 중단 시점까지의 모델 저장. 이어서 학습하는 기능은 없음 |
| 결과 폴더 | `results/설정이름_날짜시각/`: `model.pt`, `config.json`(설정 기록), 학습 기록 |

**학습 후**

1. 주행 화면 3 에피소드로 실패 위치와 원인을 확인한다.
2. `--episodes 100 --nogui`로 지표를 측정한다. 첫 실행은 평가용 교통 상태 100개 생성으로 약 45분이 추가된다.
3. [실험 기록표](experiments.md)에 설정, 지표, 관찰 내용, 모델 위치를 기록한다.
4. 다음에 바꿀 변수 하나를 정해 새 설정으로 학습한다.

소요 시간(측정값): 주행 초당 약 25–40스텝, 에피소드 시작 약 4초. 20만 스텝은 수 시간이 걸리므로 후보 설정은 5만 스텝으로 먼저 비교한다.

## 9. 학습 방식 (제안)

기준선, BC, BC 초기화 PPO 순서로 진행하고, 짧은 구간에서 시작해 전체 경로로 확장한다.

| 단계 | 방식 | 근거 |
|---|---|---|
| 1 | 기준선 (SUMO 기본 주행) | 비교 기준, BC 학습 데이터 |
| 2 | BC (기준선 모방) | 무작위 초기 정책은 2.8 km 경로를 거의 완주하지 못해 학습 신호가 적음 |
| 3 | BC 초기화 PPO | 모방 정책에서 출발해 보상 기반으로 개선 |
| 4 | 구간별 학습 후 전체 경로 | 실패 원인 파악이 쉽고, 구간 학습 자체가 비교 실험 |

| 항목 | 내용 |
|---|---|
| 보상 | 신호 위반 벌점 추가, 충돌 벌점을 속도 보상 합보다 크게, `gamma` 0.995부터 |
| 신호 | 벌점으로 정책이 학습. 11/21까지 수렴하지 않으면 신호 준수만 SUMO에 맡기는 방식으로 전환 |
| 비교 | 모든 방식을 같은 평가 시드 100개로 비교. 실패한 시도도 기록 (최종발표의 문제 해결 과정 자료) |
| 미구현 | 학습 환경 안의 기준선, BC 모델의 PPO 초기값 이식 코드, 구간별 설정 |

11/17 이후 Trial 분담 예: 보상 / 관측·`gamma` / BC, BC 초기화 PPO / 구간별 학습

## 10. 증상별 조정 변수

| 증상 | 조정 변수 |
|---|---|
| 충돌 빈발 | `collision_penalty`, `close_gap_penalty` 증가 |
| 정지 유지, 시간 초과 | `speed_weight` 증가, `collision_penalty` 감소 |
| 빨간불 통과 | 신호 위반 벌점 추가 또는 증가 |
| 차로 변경 없음 | `lane_entropy_coef` 증가, `lane_keep_bias` 감소 |
| 회전 전 차로 미확보 | `visibility` 증가, 경로 기준 차로 관측 점검 |
| 도착 미달 | `gamma`, `arrival_bonus` 증가 |
| 보상 곡선 진동 | `lr` 감소 |

## 12. 환경 보완 작업 (팀원 1)

| 순서 | 항목 | 내용 |
|---|---|---|
| 1 | 신호 관측 | `_get_obs`를 재정의해 기존 31개 뒤에 신호 값을 추가하고, `obs_dim`과 `observation_space`를 다시 생성. `signal_info()` 사용 |
| 2 | 경로 기준 차로 | 수업 코드의 연결성 값은 다음 도로로 이어지기만 하면 1이므로 회전에 필요한 차로를 알 수 없음. TraCI `getBestLanes`(`userdoc/TraCI/Vehicle_Value_Retrieval.html`)로 필요한 차로 변경 수 확인 |
| 3 | 교차로 측면 차량 | 오거리·회전교차로의 측면 접근 차량이 관측되지 않음. 11/17 이후 진행 가능 |
| 4 | 안전 제어 | `speedMode=0`(SUMO 안전 제어 전체 해제) 유지 여부 결정 (`userdoc/TraCI/Change_Vehicle_State.html`) |
| 5 | 제한속도 | `vmax`가 시속 50 km로 고정되어 교내(시속 20 km)에서 위반 가능 |

## 13. 작업 규칙

1. 같은 환경 버전끼리만 비교한다. 팀원 1이 환경을 바꾸면 실험 기록표의 버전을 올린다.

4. 실패한 시도도 [실험 기록표](experiments.md)에 기록한다.
5. 설정 파일은 `rl/configs/`에 올린다. `results/`, `data/`는 올리지 않는다.
