# 개념 정리

[작업 가이드](work_guide.md)보다 먼저 읽는 문서다. 실행 명령은 7장에 있다.

---

## 1. 팀과 학습의 역할 구분

주행 로직은 팀이 직접 작성하지 않는다. 팀은 도로·교통, 보상, 관측을 설계하고, 신경망이 시행착오를 통해 주행을 학습한다.

| 구분 | 팀이 정하는 값 | 학습으로 바뀌는 값 |
|---|---|---|
| 대상 | 보상 규칙, 관측 항목, 학습 설정(`gamma` 등) | 신경망 가중치 약 7만 개 |
| 의미 | 좋은 주행의 기준, AV가 볼 수 있는 정보 | 상황별 주행 판단 |
| 위치 | `rl/configs/*.py`, `rl/skku_env.py` | `results/*/model.pt` |

AV는 SUMO 안의 차량 1대다. 학습한 모델을 불러오면 이 차량이 모델의 판단으로 주행하고, 평가·영상·데이터는 모두 이 상태에서 얻는다. 실제 차량으로 옮기는 단계는 없다.

## 2. AV의 판단 범위

| 항목 | 내용 |
|---|---|
| 경로 | 미리 지정한다. 교차로 진행 방향은 경로에 따라 SUMO가 처리한다 |
| 신경망 출력 | 0.5초마다 가감속, 차로 변경(왼쪽·유지·오른쪽) |
| 차로 선택 | 신경망이 담당한다. 회전 전에 해당 차로로 옮기지 못하면 차로 끝에서 정지한다 |
| 신호 준수 | 신경망이 학습해야 한다. SUMO의 안전 제어는 꺼져 있다 |

## 3. 비교 방식: 기준선, BC, PPO

| 방식 | 주행 주체 | 학습 |
|---|---|---|
| 기준선 | SUMO 기본 주행 규칙 (일반 차량과 동일) | 없음 |
| BC (모방 학습, Behavior Cloning) | 신경망. 기준선 주행을 모방 | 기준선 데이터로 학습, 보상 미사용 |
| PPO (강화학습) | 신경망. 직접 주행하며 보상으로 개선 | 보상 기반 학습 |

`sumo/skku_map/view_av_route.py` 화면의 주황색 차량이 기준선 주행이다. 학습 없이도 경로를 완주한다. 이 기준선을 학습 환경에서 같은 조건으로 실행해 지표와 데이터를 얻는다. 행동 값은 SUMO가 낸 값이 아니므로 속도와 차로 변화에서 역산하며, 이 데이터가 BC의 학습 데이터가 된다.

**계획 순서**

1. 기준선: SUMO 기본 규칙으로 주행하며 관측과 역산한 행동을 기록한다.
2. BC: 1의 데이터로 기준선 주행을 모방하도록 신경망을 학습한다.
3. PPO: 2의 신경망을 초기값으로 두고 보상 기반으로 추가 학습한다.

**BC의 한계.** 기준선은 실수가 없기 때문에 데이터에 실수 이후의 복구 과정이 없다. 따라서 BC 정책이 데이터 범위를 벗어나면 오차가 누적된다. 이를 분포 이동(distribution shift)이라 하며, 3단계의 PPO 추가 학습은 이 한계를 보완하기 위한 것이다.

**비교 대상.** 기준선, BC, PPO(초기화 없이 학습), BC 초기화 PPO 네 가지다. 마지막 두 결과를 비교해야 BC 초기화의 효과를 확인할 수 있다.

**미구현 항목.** 학습 환경 안의 기준선, BC 모델을 PPO 초기값으로 옮기는 코드. 수업 코드의 BC와 PPO는 신경망 구조가 달라 그대로 연결되지 않는다.

## 4. PPO 학습 원리

### 보상과 가치

| 구분 | 보상 (reward) | 가치 (value) |
|---|---|---|
| 정하는 주체 | 팀 | PPO가 학습 |
| 학습 중 변화 | 고정 | 계속 갱신 |
| 의미 | 0.5초마다 받는 점수, 좋은 주행의 기준 | 현재 상황에서 앞으로 받을 점수의 예측값 |

보상은 구간별로 따로 주지 않는다. 경로 전체에 같은 규칙을 0.5초마다 적용한다. PPO는 구간이 아니라 관측 값으로 상황을 구분하며, 관측이 비슷하면 판단도 비슷하다.

### 업데이트 1회 과정

1. 현재 신경망으로 2048스텝(약 17분 분량)을 주행하며 관측, 행동, 보상을 기록한다.
2. 각 행동 이후에 받은 보상의 합을 가치(예측값)와 비교한다. 이후 보상은 `gamma`로 할인해 더하므로, 충돌 직전 몇 초 동안의 행동이 충돌 벌점을 나누어 받는다.
3. 예측보다 결과가 좋았던 행동은 해당 상황에서의 선택 확률을 조금 높이고, 나빴던 행동은 조금 낮춘다. 한 번의 변화량은 일정 범위로 제한한다(clip).
4. 가치 예측값도 실제 결과 쪽으로 조금 갱신한다.
5. 이 과정을 반복한다. 20만 스텝이면 약 100회다.

PPO는 신호의 의미를 이해하지 않는다. 특정 관측에서 감속한 결과가 예측보다 좋았던 경험이 누적되면서 감속 확률이 높아지고, 그 결과 빨간불에서 정지하게 된다.

### 예시: 빨간불 접근

보상 규칙(예시): 0.5초마다 속도에 비례해 최대 +0.1, 빨간불 통과 -10, 충돌 -20

상황: 사거리 30 m 앞, 빨간불, 시속 40 km. 이 상황의 가치 예측값은 약 -4다.

| 항목 | 시도 A | 시도 B |
|---|---|---|
| 행동 | 가속 | 감속 |
| 이후 경과 | 빨간불 통과 | 정지선에서 20초 대기 후 출발 |
| 이후 보상 합 | 약 -9 | 약 +1 |
| 예측값(-4) 대비 | 5점 낮음 | 5점 높음 |
| 확률 변화 | 이 상황에서 가속 확률 감소 | 이 상황에서 감속 확률 증가 |

반복 학습 후에는 빨간불 접근 시 감속 확률이 1에 가까워진다. 다만 이 학습은 관측에 신호 색과 거리가 있어야 가능하다. 현재 관측에는 신호 정보가 없어 빨간불과 초록불 상황이 구분되지 않으며, 이 때문에 신호 관측 추가가 첫 작업이다.

## 5. 학습 반복 과정

1. 팀이 보상, 관측, 설정을 정한다.
2. PPO가 그 규칙으로 학습한다.
3. 평가 지표와 주행 화면으로 결과를 확인한다.
4. 의도와 다르면 원인 하나를 수정하고 다시 학습한다.

PPO의 개선은 주어진 보상 규칙 안에서만 일어난다. 규칙에 빈틈이 있으면 정책은 그 빈틈을 이용한다. 예를 들어 신호 위반 벌점이 없으면 신호를 위반하는 행동이 이득으로 학습된다.

**원인 구분**

| 원인 | 증상 예 | 수정 대상 |
|---|---|---|
| 보상 규칙의 빈틈 | 충돌 벌점이 작아 고속 주행 중 충돌, 벌점이 커서 정지 상태 유지 | `REWARD` |
| 관측 정보 부족 | 신호 정보가 없어 빨간불 구분 불가 | `rl/skku_env.py`의 관측 |
| 학습량 부족, 학습 불안정 | 보상 곡선이 계속 상승 중이거나 크게 진동 | `TOTAL_TIMESTEPS`, `lr`, `gamma` |

주행 화면에서는 원인이 보상, 관측, 학습량 중 어디인지부터 구분한다. 증상별 조정 변수는 작업 가이드 10장에 있다.

**목표 (평가 기준의 통과선)**

| 항목 | 기준 |
|---|---|
| 충돌률 | 5% 미만 (평가 100 에피소드) |
| 완주 | 목적지(교내 L1 주차장) 도착 |
| 비정상 동작 | 이유 없는 정지, 경로 이탈 없음 |

통과선 이후에는 평균 주행 시간과 보상으로 기준선 대비 성능을 비교한다.

## 6. 데이터 칼럼과 설정 변수

| 구분 | 데이터 칼럼 | 설정 변수 |
|---|---|---|
| 정의 | 0.5초마다 기록되는 항목 (데이터 표의 열) | 학습 전에 정하는 값 |
| 예 | `reward`, `observation`, `event.collided` | `collision_penalty`, `gamma` |
| 값의 결정 | 주행 결과로 기록 | 팀이 지정 |

설정 변수를 바꾸면 주행이 달라지고, 그 결과 칼럼에 기록되는 값이 달라진다. `observation`은 정책의 입력(부분 관측)이고, `state`는 분석용 시뮬레이터 상태다.

## 7. 실행 명령

**터미널.** PowerShell, 명령 프롬프트, VS Code 터미널 모두 사용할 수 있다. 실행 위치는 팀 저장소 최상위 폴더(`autonomous-driving`)이며, 예외는 표에 표시했다. `-X utf8`은 한글 출력이 깨지지 않게 하는 옵션이다.

**터미널 구성 (학습 시)**

| 터미널 | 용도 |
|---|---|
| 1 | 학습 (수 시간 실행) |
| 2 | `tensorboard --logdir results` (학습 곡선, 학습 중 계속 실행) |
| 3 | 학습이 끝난 모델의 평가와 주행 확인 |

**명령**

| 용도 | 명령 | 결과 |
|---|---|---|
| 실행 확인 | `python -X utf8 rl/train_skku.py --config example --timesteps 2048` | 1–2분, `results/`에 결과 폴더 생성 |
| 학습 | `python -X utf8 rl/train_skku.py --config 설정이름` | `results/설정이름_날짜시각/model.pt` |
| 학습 곡선 | `tensorboard --logdir results` | 브라우저 `localhost:6006` |
| 주행 화면 | `python -X utf8 rl/test_skku.py results/폴더/model.pt --config 설정이름 --episodes 3` | sumo-gui 창, 빨간 차량이 AV |
| 구간 지정, 재생 속도 | 주행 화면 명령에 `--start 회전교차로 --delay 20` 추가 | 구간: 사거리, 버스, 오거리, 회전교차로, 일월로, 정문 |
| 100 에피소드 평가 | `python -X utf8 rl/test_skku.py results/폴더/model.pt --config 설정이름 --episodes 100 --nogui` | 충돌률, 완주율, 평균 속도, 보상 |
| 데이터 수집 | `python -X utf8 rl/collect_skku.py --config 설정이름 --model results/폴더/model.pt --episodes 20` | `data/`에 `.jsonl.gz`, `.npz` |
| BC 학습 | 수업 저장소 폴더에서 `python train_bc.py --data <npz 경로>` | 수업 저장소 `results/bc_*` |
| 칼럼 과제 형식 CSV | `python -X utf8 rl/make_column_sample.py 출력.csv` | 16줄 CSV |
| 도로·교통 확인 | `sumo/skku_map` 폴더에서 `python -X utf8 view_av_route.py` | 기준선 주행(SUMO 기본 승용차) |
| 도로·교통 재생성 | `sumo/skku_map` 폴더에서 `python -X utf8 build.py --no-check` | 교통·신호 수정 후 실행 |

- `--config` 값은 학습할 때의 설정 이름과 같아야 한다. 네트워크 구조가 같아야 모델을 불러올 수 있다.
- 학습 중 `Ctrl + C`로 중단해도 중단 시점까지의 모델이 저장된다.
- 화면 조작(일시정지, 한 스텝 진행, 재생 속도, 차량 추적)은 작업 가이드 5장에 있다.
