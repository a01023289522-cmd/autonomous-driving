# Fork 사용법 (팀원 필독)

**Fork**는 Git을 화면으로 쓰게 해주는 프로그램이다. 명령어 없이 클릭으로
최신 코드 받기, 내 변경 올리기, 누가 무엇을 바꿨는지 보기를 할 수 있다.

> 메뉴 이름·위치는 Fork 버전이나 Windows/Mac에 따라 조금 다를 수 있다.
> 이 문서는 흐름 위주로 보고, 막히면 팀 채팅에 물어본다.

---

## 1. 처음 한 번만 하는 설정

### 1-1. 설치
- https://git-fork.com 에서 Windows / Mac 버전을 받아 설치한다.
- 무료 평가판으로 계속 쓸 수 있다 (정식 라이선스는 유료, 가끔 구매 안내 창이 뜬다).

### 1-2. 이름과 이메일
- 처음 실행하면 Git에 쓸 **이름과 이메일**을 묻는다. GitHub 계정 이메일을 넣는다.
  (커밋에 "누가 바꿨는지"로 남는다)

### 1-3. GitHub 계정 연결
- Windows: `File → Accounts`
- Mac: `Fork → Settings(Preferences) → Accounts`
- `+` → **GitHub** → 브라우저에서 로그인·승인.

### 1-4. 저장소 초대 수락
- 이 저장소는 **비공개**라서 초대를 받아야 보인다.
- GitHub 이메일 또는 https://github.com/notifications 에서 초대를 **수락**한다.

### 1-5. 저장소 받기 (Clone)
- `File → Clone…`
- Repository URL: `https://github.com/a01023289522-cmd/autonomous-driving.git`
- 저장할 폴더를 고르고 `Clone`.

## 2. 화면 구성

```text
┌───────────────┬──────────────────────────────────────────────┐
│ 왼쪽 사이드바   │  가운데: 커밋 기록 그래프 / 변경된 파일 목록        │
│               │                                              │
│ Local Changes │  ← 내가 바꾼 파일 (아직 올리지 않은 것)            │
│ All Commits   │  ← 전체 변경 기록                                │
│ Branches      │  ← 내 컴퓨터의 브랜치 (더블클릭 = 이동)             │
│ Remotes       │  ← GitHub에 있는 브랜치                          │
│ Stashes       │  ← 임시로 치워둔 변경                             │
├───────────────┴──────────────────────────────────────────────┤
│ 위쪽 툴바: Fetch · Pull · Push · Stash · Branch …              │
└──────────────────────────────────────────────────────────────┘
```

| 버튼 | 하는 일 |
|---|---|
| **Fetch** | GitHub에 새 변경이 있는지 **확인만** (내 파일은 안 바뀜) |
| **Pull** | GitHub의 최신 변경을 **내 컴퓨터로 받아옴** |
| **Push** | 내가 커밋한 변경을 **GitHub에 올림** |
| **Branch** | 새 작업 브랜치 만들기 |
| **Stash** | 아직 커밋 안 한 변경을 잠깐 치워두기 |

## 3. 매번 하는 작업 흐름

```text
① Pull (최신 받기)
② 새 브랜치 만들기
③ 파일 수정
④ Stage → Commit (변경 기록 남기기)
⑤ Push (GitHub에 올리기)
⑥ GitHub에서 Pull Request 만들기 → 팀원 확인 → main에 합치기
```

### ① 작업 시작 전: Pull
- 사이드바 `Branches`에서 **`main`을 더블클릭**해서 main으로 이동 → 툴바 **Pull**.
- 남이 올린 최신 내용 위에서 시작해야 충돌이 적다.

### ② 브랜치 만들기
- 툴바 **Branch** → 이름 입력 → `Create and checkout`(만들고 이동) 체크.
- **브랜치 이름 규칙: `이름/작업내용`** (영어 소문자, 띄어쓰기는 `-`)
  - 예: `junsoo/road-intersection`, `minki/reward-signal`

### ③ 파일 수정
- 평소처럼 VS Code 등으로 파일을 고치고 저장한다.
- Fork의 **Local Changes**에 바뀐 파일이 나타나고, 파일을 누르면 **바뀐 줄**(초록 = 추가, 빨강 = 삭제)이 보인다.

### ④ Stage → Commit
- 올릴 파일을 선택하고 **Stage** (또는 파일을 위쪽 Staged 칸으로 이동).
- 아래 칸에 **커밋 메시지**를 쓰고 **Commit**.
- **커밋 메시지 규칙: `분류: 무엇을 했는지`** (한글 OK)
  - 예: `도로: 사거리 노드와 엣지 추가`, `보상: 신호 위반 감점 추가`, `문서: 회의 기록 추가`
- 작은 단위로 자주 커밋한다. 한 커밋에 여러 작업을 섞지 않는다.

### ⑤ Push
- 툴바 **Push** → 처음 올리는 브랜치면 GitHub에 같은 이름으로 만들어진다
  (`Create tracking reference` 같은 체크가 보이면 켜둔다).

### ⑥ Pull Request (PR)
1. GitHub 저장소 페이지에 들어가면 노란 배너 **`Compare & pull request`** 가 뜬다 → 클릭.
2. 제목·설명에 **무엇을 왜 바꿨는지** 쓴다.
3. 오른쪽 **Reviewers**에 팀원 1명 지정.
4. 팀원이 확인하고 **`Merge pull request`** → main에 합쳐진다.
5. 합쳐진 뒤 Fork에서 main으로 이동 → **Pull** → 다음 작업은 다시 ②부터.

## 4. 충돌(Conflict)이 났을 때

두 사람이 **같은 파일의 같은 부분**을 다르게 고치면 Pull이나 Merge 때 충돌이 난다.

1. Fork가 충돌 난 파일을 표시한다 (Local Changes에 경고 아이콘).
2. 파일을 누르면 **내 것(Ours / Mine)** 과 **상대 것(Theirs)** 을 비교하는 화면이 나온다.
3. 줄마다 어느 쪽을 남길지 고르거나 직접 합친다 → 저장.
4. 해결한 파일을 Stage → Commit.

> 혼자 판단이 어려우면 **바로 Commit 하지 말고** 그 부분을 고친 팀원과 상의한다.
> 충돌을 줄이려면: 작업 전 Pull, 작은 단위로 자주 PR, 같은 파일을 동시에 크게 고치지 않기.

## 5. 기록 보기

- **All Commits**: 전체 변경 기록. 커밋을 누르면 그때 바뀐 파일과 줄이 보인다.
- 파일 **오른쪽 클릭 → File History**: 그 파일이 언제 누가 어떻게 바뀌었는지.
- 파일 **오른쪽 클릭 → Blame**: 각 줄을 마지막으로 바꾼 사람과 커밋.

## 6. 팀 규칙 요약

| 규칙 | 이유 |
|---|---|
| `main`에 직접 커밋하지 않는다 | main은 항상 실행되는 상태로 유지 |
| 작업 전 항상 Pull | 충돌 예방 |
| 브랜치 이름 `이름/작업내용` | 누가 무슨 작업 중인지 바로 보임 |
| 커밋 메시지 `분류: 내용` | 기록만 봐도 무엇이 바뀌었는지 알 수 있음 |
| PR은 팀원 1명 확인 후 Merge | 실수 방지, 서로 작업 공유 |
| `results/`, 큰 데이터, `__pycache__` 는 올리지 않는다 | 저장소가 무거워짐 (`.gitignore`에 등록됨) |
| 실험·결정은 [진행 계획](roadmap.md)에 기록 | 나중에 보고서 쓸 때 근거가 됨 |

## 7. 자주 하는 실수

| 상황 | 해결 |
|---|---|
| Push가 거절됨 (rejected) | 그 사이 다른 사람이 올린 것. **Pull 먼저** 하고 다시 Push |
| main에서 작업해버림 | 커밋 전이면: 툴바 Branch로 새 브랜치를 만들면 변경도 같이 따라온다 |
| 커밋 메시지를 잘못 씀 | Push 전이면 마지막 커밋 오른쪽 클릭 → 메시지 수정(Edit/Amend) 메뉴 |
| 실수로 지운 파일 | Local Changes에서 파일 오른쪽 클릭 → Discard (되돌리기). 단, **커밋 안 한 변경은 영영 사라지니** 신중하게 |
| 저장소가 안 보임 | 초대를 수락했는지 확인 (1-4) |
